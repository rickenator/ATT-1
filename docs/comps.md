# ATT-1 / AIMU Architecture Comparison (M154 Context)

**Deeper comparison to recent NVIDIA (Blackwell/Rubin + TensorRT-LLM) and Apple (M4 Neural Engine + Apple Intelligence) production systems.**

Builds on `docs/aimu_architecture.md:90-99` ("Why AIMU Is Different from GPU/TPU Acceleration") and prototype mapping (lines 107-116). Emphasizes ATT-1's memory-centric tiled ownership + explicit control-plane governance vs. conventional compute-centric pull-from-hierarchy models. M153 beachhead (long-context, high-KV decode) and governance artifacts referenced throughout.

## Summary Insights
- **ATT-1's Core Advantage**: By making tensor **ownership**, **placement**, and **routing** first-class, auditable artifacts (rather than runtime heuristics), it targets the bandwidth wall in long-context LLM decode more directly than pull-based GPU/TPU or on-device ANE designs. This aligns with Rubin’s bandwidth focus but adds explicit governance and determinism that production stacks often treat as secondary.
- **Trade-offs**: ATT-1 is deliberately narrow (decoder-only inference, C11-only runtime, no training, userspace-first per M153 contract). NVIDIA/Apple optimize for massive scale/ecosystem or power efficiency respectively.
- **Alignment with Workflow**: Supports M153 "evidence-gated" and "governance artifacts as product value" pillars. No runtime changes; documentation-only. M155 CUDA signoff is complete and M156 gap audit is the next milestone.
